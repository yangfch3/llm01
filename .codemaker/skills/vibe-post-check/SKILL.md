# Vibe 后处理流程

在一轮 Vibe Coding 结束后执行此流程，确保文档和 rules 与代码实现保持同步。

## 执行步骤

### 1. 文档同步检查

回顾本次会话中所有代码改动，逐项检查：

- **需求文档**（`Doc/DesignDoc/`）：本次改动关联的设计文档是否反映了最终实现？重点关注接口签名、数据结构、流程描述是否与代码一致。
- **技术文档**（`Doc/EngineDoc/`）：本次新增或修改的框架能力是否有对应的使用指南？已有指南的内容是否需要更新？

如发现滞后，直接执行更新。

### 2. Rules 同步检查

判断本次改动是否属于**框架级别**变更——即新增/修改了 Core、Def、基类、框架模式、全局工具函数等会影响后续开发规范的内容。

- **是框架级变更**：更新 `.codemaker/rules/rules.mdc` 中对应章节（§6 关键框架模式、§11 工具函数速查、§12 常量定义位置等）。
- **非框架级变更**（纯业务模块、UI 窗口、具体玩法逻辑等）：无需更新 rules。

### 3. 输出结论

对每项检查给出一行结论，格式：

```
- 需求文档 XXX.md：已是最新 / 已更新（说明改了什么）
- 技术文档 XXX.md：已是最新 / 已更新 / 无需新增
- rules.mdc：已是最新 / 已更新（说明改了什么）/ 无需更新（非框架级变更）
```

不要展开解释，不要长篇大论。
